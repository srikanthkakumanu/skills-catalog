# Implementation Guide Skill

## Directives
1. Runs after `PRD.md` exists — never before, and never consulted by `brd`, `req-nfr-analysis`, `architecture-decisions`, `detailed-design`, `tech-stack`, or `prd`. This is the one skill in the pipeline downstream of the single source of truth, not upstream of it.
2. Resolve, never decide — every context it writes conventions for must already be `status: confirmed` in `tech-stack.md`. A context still `pending` there is out of scope here; route back to `tech-stack` rather than guessing a stack for it.
3. Per confirmed context, resolve the cited playbook's path to its "Implementation detail" topic list, then resolve each topic by the context's language: a `stacks/springboot4-*.md` citation resolves against the matching `skills/<category>/<topic>/` folder(s) — one of this catalog's standalone Spring Boot 4.x reference skills (see this skill's `README.md` for the category map); a `stacks/python-ai-agentic.md` citation resolves against the matching `conventions/python/<topic>.md` file(s) — plain reference files, not independently-triggerable skills.
4. Cite the source path in project conventions output — never re-explain or paraphrase its content; the guide/convention file is the reference, the convention doc is a pointer plus house-specific additions (build tool, language version) only.
5. Java 27 only, Gradle Groovy DSL only — inherited from `tech-stack/stacks/java-baseline.md` and stated identically in `java-language-conventions/SKILL.md`, which also carries language-feature usage guidance (records, sealed types, pattern matching, virtual threads) — loaded unconditionally for every Java context, never resolved per-context the way `skills/<category>/<topic>/` topics are. Never introduce a different Java version or a Kotlin DSL example.
6. Python 3.11.x — inherited from `compatibility-baseline.md` and stated in `conventions/python/language-conventions.md`, loaded unconditionally for every Python context (type hints, Pydantic v2, Ruff, async discipline). Capability-specific Python files (`mcp-server.md`, `langgraph-orchestration.md`, `langchain-integration.md`, `ai-observability.md`) are resolved per-context by citation only, the same way `skills/<category>/<topic>/` topics are for Java. Never introduce a different Python version.
7. **Cost control** — resolving a citation to a folder or file path and formatting a conventions file is lookup and formatting, not judgment. If a step seems to need weighing options, that step belongs in `tech-stack`, not here — flag it upstream instead of doing it.
8. **Context** — read `tech-stack.md` once to collect confirmed contexts and their cited playbooks; read each cited guide/convention file once when resolving it, not per context that happens to share it.

## Process
1. Confirm `PRD.md` exists. If not, stop — this skill has nothing valid to resolve yet.
2. Read `tech-stack.md`. Collect every `status: confirmed` row's playbook citation. Any `pending` or `under-constrained` row is out of scope — note it, don't resolve it.
3. For each cited playbook, read its "Implementation detail" line and resolve each topic name — against `skills/<category>/<topic>/` for a Java/Spring Boot playbook (see this skill's `README.md` for the category map), or against `conventions/python/<topic>.md` for the Python AI-agentic playbook.
4. Emit `CLAUDE.md` and `AGENTS.md`: the baseline matching the context's language — Java 27 + Gradle Groovy (`java-language-conventions/SKILL.md`, `spring-boot-conventions/SKILL.md`) for Java contexts, Python 3.11.x (`conventions/python/language-conventions.md`) for Python contexts — then per-context pointers to the resolved paths, not their content.
5. If a resolved guide/convention file's stated prerequisite conflicts with a project fact already confirmed upstream (e.g. a Java or Python version other than the baseline), flag it as an Open Item — never silently resolve the conflict here.

## Output: `CLAUDE.md`, `AGENTS.md`
Project-root convention files, in order: (1) a provenance header citing `PRD.md` as the source of truth and `implementation-guide` as the generating skill (e.g. "Generated by `implementation-guide` from `PRD.md` — regenerate via that skill if `PRD.md` changes"); (2) the house baseline matching each confirmed context's language (Java 27 + Gradle Groovy from `conventions/`, or Python 3.11.x from `conventions/python/`); (3) one section per confirmed bounded context naming its stack and pointing to the resolved `skills/<category>/<topic>/` or `conventions/python/` paths.

## Out of Scope
- Any architecture, stack, or requirement decision — those are `tech-stack.md`'s and upstream's, already closed by the time this skill runs.
- Resolving a `pending` or `under-constrained` context — route back to `tech-stack` instead.
- Inlining guide content into the conventions output — point to the path; the guide itself is the detail.
